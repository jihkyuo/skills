# 하네스 어댑터 — Claude Code (Orca 없음)

Claude Code의 Agent 도구로 슬롯마다 워커를 띄운다. 워커는 백그라운드에서 돌고 끝나면 알림이 오며, **같은 에이전트에 SendMessage로 후속 메시지를 보내면 컨텍스트를 유지한 채 이어진다.** 그래서 이 스킬의 핵심인 작가 연속이 성립한다. 잃는 것은 터미널 관찰이라 기동 확인을 자가 보고로 대체한다.

## 기동

슬롯마다 Agent 도구 호출 하나. 한 응답에서 N개를 같이 호출하면 병렬로 돈다.

- `subagent_type`: general-purpose (fresh · 코디의 대화 컨텍스트를 상속하지 않는다. `fork`는 쓰지 않는다 — 코디의 해석이 워커에 스민다).
- `model`: 씨드가 정한 모델.
- `prompt`: task spec 본문 그대로 + 절대경로. «첫 행동 = 씨드가 지정한 디자인 스킬을 Skill 도구로 로드» 문장을 그대로 둔다.
- 워커에게 «시작 1분 안에 `<slot>/_wip/status.md`에 로드한 스킬 이름과 모델을 한 줄 써라»를 추가한다. 이것이 기동 확인의 대체물이다.

## 기동 확인

디스패치 약 1분 뒤 `<slot>/_wip/status.md`를 읽는다. 스킬 로드가 없으면 그 에이전트에 SendMessage로 시정. Enter 레이스는 없다(프롬프트가 곧 제출이다).

## 대기

완료 알림이 오므로 정산 폴링은 필요 없다. 착지(v1)는 알림 전에 일어나므로 슬롯 파일 크기 안정화만 Monitor(또는 짧은 셸 루프)로 본다. 알림을 «완료»로 읽지 말고 파일을 확인한다.

## 후속 메시지 (작가 연속)

SendMessage로 그 에이전트의 id를 지정해 피드백 task spec을 보낸다. 워커에게 미리 «v2 제출 뒤 턴을 끝내고 후속 메시지를 기다려라»고 써 두면 세션이 살아 있는 채 멈춘다. 이미 끝난 에이전트에도 SendMessage는 컨텍스트를 이어 재개한다. 재개가 안 되면 Phase 4의 재수화.

## 실측 도구

- 스크린샷·클릭 프로브: Chrome MCP(claude-in-chrome)가 있으면 그것, 없으면 Playwright(`npx playwright screenshot`, 스크립트로 클릭 전/후 캡처). gstack이 설치돼 있으면 `browse`.
- 무대 서버: `nohup python3 -m http.server <port>`.

## 릴리스

없다. 에이전트는 턴이 끝나면 쉬고 있고, SendMessage로 다시 부른다. 눈 게이트 판정 전에는 새 에이전트로 갈아타지 않는다.
