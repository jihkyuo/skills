# 하네스 어댑터 — 범용 (Codex · Cursor · Gemini CLI · 수동)

서브에이전트를 코드로 띄우지 못하는 환경이거나 다른 에이전트를 쓸 때의 최소 경로다. 코디네이터는 사용자의 메인 세션이고, 워커는 사람이 여는 에이전트 세션 N개다. 절차는 같고 손이 더 간다.

## 기동

- 슬롯마다 터미널(또는 에디터 창) 하나를 열고 에이전트 세션을 시작한다. 가능하면 워크트리·폴더를 분리한다.
- task spec 본문을 그대로 붙여 넣는다. 첫 줄의 «첫 행동 = 씨드가 지정한 디자인 스킬 로드»는 그 에이전트의 스킬 로드 방식으로 바꾼다(스킬 설치: `npx skills add anthropics/skills@frontend-design -a <agent>`).
- 워커에게 «시작 직후 `<slot>/_wip/status.md`에 로드한 스킬과 모델을 한 줄 써라».

## 기동 확인

각 세션 화면에서 직접 본다. 프롬프트 제출·모델·스킬 로드 세 가지. 없으면 그 세션에 시정 문장을 붙여 넣는다.

## 대기

슬롯 파일 크기 안정화를 셸 루프로 본다:

```bash
while :; do for s in a b c; do printf "%s %s  " "$s" "$(wc -c < "$s/index.html" 2>/dev/null || echo 0)"; done; echo; sleep 20; done
```

변화가 멈춘 슬롯이 착지다. 정산은 워커가 «worker_done» 문면을 세션에 출력하는 것으로 갈음한다.

## 후속 메시지 (작가 연속)

같은 세션에 피드백 task spec을 붙여 넣는다. 세션을 닫았으면 Phase 4의 재수화(자기 파일 + 원 브리프 + 원문)로 새 세션을 연다.

## 실측 도구

Playwright CLI 또는 각 에이전트의 브라우저 도구. 최소한 슬롯마다 «상태별 스크린샷 1장 + 핵심 클릭 전/후 캡처»는 코디가 직접 확보한다. 무대 서버는 `python3 -m http.server`.

## 릴리스

세션을 닫는 것이 릴리스다. 눈 게이트 판정 전에는 닫지 않는다.
