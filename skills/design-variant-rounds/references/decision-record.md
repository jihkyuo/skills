# 결정 기록 — 라운드 마감 때 무대에 남기는 문서

확정안이 정식 구현 라운드로 넘어갈 때 «왜 이것인가»가 함께 가야 구현이 시안을 되묻지 않는다. 결정마다 아래 7항. 결정을 내리는 중에 쓰고, 끝나고 재구성하지 않는다.

```markdown
# <주제> 결정 기록 — <날짜>

## 결정 N: <무엇을 골랐나 — 구체적으로>
- **맥락**: 어떤 문제·요구가 이 결정을 불렀나. 제약은.
- **고려한 안**: 라운드에서 나란히 본 변형들(슬롯·이름) 한 줄씩.
- **증거**: 사용자 눈 게이트 원문, 실동작·계측, 수령 리뷰의 근거.
- **이유**: 왜 이 안이 다른 안보다. 사용자 요구·제품 원칙·기술 가능성에 잇는다.
- **트레이드오프**: 알고 감수한 것. 무엇을 뒤로 미뤘고 왜.
- **검증 계획**: 이 결정이 맞았는지 무엇으로 아나(실브라우저 확인 항목·지표).
- **구현 메모**: 시안이 실구현과 갈리는 지점, 장부 등재 대상.
```

## 품질 체크

- 사용자 요구에 이어져 있나(코디 선호가 아니라).
- 대안과 트레이드오프를 인정했나.
- 몇 달 뒤 읽어도 쓸모 있을 만큼 구체적인가.
- 읽을 사람(구현 라운드 워커·BE·기획)에게 맞는 말로 썼나.

## 함께 남기는 것

- `_archive/`: 탈락·중간 세대 슬롯(지우지 않는다. 다음 라운드의 «기운 방향»을 되짚을 재료다).
- compare.html: 확정안 직행 리다이렉트.
- 계약 부록: 확정으로 굳은 것만 조문화. 라운드 중의 «임시 게이트»는 부록에 올리지 않는다.
